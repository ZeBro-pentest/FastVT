Сегодня в системе: !`date "+%d.%m.%Y, %A"`
Ветка: !`git branch --show-current`

Планы проекта по дням:
@ROADMAP.md

Правила проекта:
@AGENTS.md

Какие спеки есть на диске: !`ls specs/`
Коммиты за сегодня: !`git log --oneline --since="midnight"`

Закрой рабочий день строго по шагам, шаги не перескакивать.

## 1. Определи задачу дня

Найди в разделе «План по дням» строку с сегодняшней датой (`ДД.ММ`).
Прочитай спеку текущей версии — файл из `specs/` по номеру версии в названии строки.
Правила и соглашения — из `AGENTS.md`, он выше приложен целиком.

## 2. Проверь факты, а не обещания

- `git log --oneline --since="midnight"` — что реально сделано за день;
- `python -m pytest -q` — сравни результат с ожиданием строки задачи
  (например «тест A7 зелёный»);
- `git status --short` — нет ли незакоммиченных изменений;
- для каждого критерия приёмки, который задача закрывает, убедись, что есть тест
  и он зелёный.

Если проверка не прошла — **день не закрывай**. Ничего не меняй, галочку не ставь,
коммит не делай. Покажи, что не так, и закончи фразой:
`день не закрыт, осталось: <что именно>`.

## 3. Покажи план и спроси подтверждение

До любых изменений выведи и дождись ответа:

- дата, день недели, задача дня, ожидаемый результат;
- какие файлы изменятся: `ROADMAP.md`, спека версии, отчёт в `history/`;
- текст будущего коммита;
- итог тестов одной строкой.

Ничего не меняй до подтверждения. Если пользователь попросил что-то изменить —
переделай план и спроси снова.

## 4. После подтверждения

1. `ROADMAP.md` — в строке сегодняшнего дня поставь `- [x]` в колонке «Готово».
   Правку делай точечно, сохрани CRLF, файл перезаписывать целиком нельзя.
2. Спека версии — если день менял поведение, поправь `specs/vX.Y.md` по сути.
   Если день приёмки — отметь, какие критерии закрыты.
3. `history/` — допиши отчёт по секции 1 из `history/README.md`: задача, что сделано,
   проверки, коммиты, открытые вопросы. Папка в `.gitignore`, в коммит не попадает.
4. Коммит маленький, только `ROADMAP.md` и спека. Формат:
   `chore(plan): день ДД.ММ закрыт — <задача из строки> (<FR или A-код>)`
5. `git push` в `ZeBro-pentest`. Перед пушем покажи `git status`, что попадает
   в коммит.

## Запрещено

- коммитить, пушить или переключаться в `main`;
- `git tag`, `git merge`, `--force`, `--amend` опубликованной истории;
- ставить галочку, если тесты красные по существу задачи дня;
- выдумывать работу, которой не было: в отчёте только то, что реально сделано;
- добавлять фичи, которых нет в спеке текущей версии.
