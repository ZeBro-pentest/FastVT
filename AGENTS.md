# AGENTS.md

Проект: генератор видео-таймера. Накладывает секундомер или обратный отсчёт на
видео, картинку или однотонный фон через ffmpeg. Интерфейсы: CLI и Tkinter GUI.
Разработка по SDD: сначала спека, потом код.

## Главное правило

Перед любой задачей прочитай спеку текущей версии: `specs/v0.1.md` (после релиза
версии — следующий файл). Общий контекст и ID требований в `SPEC.md`, план по дням
в `ROADMAP.md`. Не реализуй ничего, чего нет в спеке текущей версии. Если задача
требует фичи вне спеки — остановись и скажи об этом, не добавляй сам.

## Стек и команды

- Python 3.10+, движок и CLI только на стандартной библиотеке.
- GUI: Tkinter, тема `ttkbootstrap` необязательна (fallback на `ttk`).
- Видео обрабатывает только ffmpeg. Покадровую обработку в Python не писать.
- Окружение: `python3 -m venv --system-site-packages venv && source venv/bin/activate`
- Зависимости: `pip install -r requirements.txt`
- Запуск GUI: `python -m video_timer.gui`
- Запуск CLI: `python -m video_timer.cli --help`
- Тесты: `python -m pytest -q`
- На WSLg для Tkinter нужна переменная `GDK_BACKEND=x11`.

## Ветки

- `ZeBro-pentest` — рабочая ветка разработки, создана 29.09.2026. Все коммиты
  идут сюда, upstream настроен, пуш обычный: `git push`.
- `main` — только готовые версии. Работать и коммитить в ней нельзя.
- Перед задачей: `git switch ZeBro-pentest`. Пуш в `main` — не делать.
- Релиз делает разработчик, не агент, и только после приёмки и тега версии:
  `git switch main && git merge --no-ff ZeBro-pentest -m "release: v0.1"`,
  затем `git tag v0.1 && git push origin main --tags`.
- Force-push запрещён, особенно в `main`. Переписать опубликованную историю
  нельзя — от неё зависит отчётность версий.
- `history/` в git не попадает: папка локальная, для журнала промптов.
  После каждой задачи дописывай туда отчёт сам, разработчик её читает.

## Архитектура

Модули лежат в `video_timer/`: `config`, `timeformat`, `background`, `filters`,
`encoders`, `estimate`, `renderer`, `osutil`, `cli`, `gui/`. Зависимости только
в одну сторону: `gui`/`cli` → `renderer` → `filters`/`background`/`encoders` → `config`.
Обратных импортов не делать. Сигнатуры модулей описаны в `SPEC.md`, раздел 7,
менять их без правки спеки нельзя.

## Соглашения

- Каждый публичный класс и функция имеет docstring в тройных кавычках: назначение,
  параметры, возвращаемое значение, исключения.
- Ошибки пользователя — `VideoTimerError` с текстом вида `«поле: что не так»`,
  на русском. Трейсбек и сырой лог ffmpeg пользователю не показывать.
- Значения `text=` и `enable=` фильтра drawtext экранировать через
  `timeformat._escape()` и `timeformat._escape_enable()`. Число обратных
  слэшей разное: в `text=` двоеточие — `\\:` (два слэша), запятая — `\,`
  (один); в `enable=` запятая — `\,`. Экранировать только исходный текст,
  повторно не обрабатывать. Проверено на ffmpeg 7.1, таблица в `SPEC.md` 7.3.
- Команду ffmpeg собирать списком аргументов, `shell=True` не использовать.
- Лог ffmpeg читать потоком, хранить не больше 50 последних строк.
- GUI не должен блокироваться: рендер только в отдельном потоке, связь через очередь.
- Тексты интерфейса и ошибок на русском.

## План на сегодня

Перед любой задачей найди в `ROADMAP.md` раздел «План по дням» и строку
с сегодняшней датой в формате `ДД.ММ`. Эта строка — задача дня: работай
по ней, а не по собственным соображениям. Назови в ответе дату, задачу
и критерии приёмки из спеки версии (`specs/vX.Y.md`).

Колонка «Готово» в таблицах плана: `- [x]` — день закрыт, `- [ ]` — нет.
Ставит галочку только команда `/final` и только после проверки, руками
не отмечать.

## Команды opencode

- `/today` — показать задачу на сегодня: дата, FR, критерии приёмки, модули
  из `SPEC.md` 7, состояние ветки. Ничего не меняет, не коммитит, тесты
  не гоняет.
- `/final` — закрыть день: прогнать тесты, сверить задачу с кодом, показать
  план и дождаться подтверждения, поставить галочку в `ROADMAP.md`, поправить
  спеку, дописать отчёт в `history/`, сделать коммит и запушить
  в `ZeBro-pentest`.

`/final` делает **один коммит на весь день**:

```
chore(plan): день ДД.ММ закрыт — <задача из строки ROADMAP.md> (<FR или A-код>)
```

В коммит попадает **всё, что сделано за день**: код модулей, тесты, `SPEC.md`,
`AGENTS.md`, `pyproject.toml` и прочие изменённые файлы, плюс `ROADMAP.md` и
спека версии `specs/vX.Y.md`. Один коммит на день, а не отдельный на код и
отдельный на план: так вся работа дня видна в истории одной записью, и её нельзя
случайно оставить незакоммиченной.

`history/` в коммит не попадает — папка в `.gitignore`, не добавлять её через
`git add -A`. Перед коммитом показать `git status --short` и `git diff
--cached --stat`, чтобы состав попадания был виден до запуска.

`/final` не коммитит и не пушит в `main`, теги не ставит, слияния не делает,
`--amend` и `--force` не использует. Если задача дня не сделана или тесты
красные по её существу — день не закрывает, а перечисляет, что осталось.

## Как работать над задачей

0. Посмотри план на сегодня (`/today`) и убедись, что задача дня совпадает
   с тем, о чём просят. Если нет — спроси, что берём.
1. Найди в спеке версии нужные FR и критерии приёмки (A1…A12).
2. Сначала напиши или обнови тест по критерию, убедись, что он падает.
3. Реализуй минимально, чтобы тест прошёл. Один модуль за раз.
4. Прогони `python -m pytest -q`.
5. Обнови docstring и, если менялось поведение, спеку. В ходе работы код
   можно коммитить по одной задаче: `feat(filters): fit=cover (FR-14)`.
   Коммит дня целиком собирает `/final`, отдельным сообщением.
6. Допиши отчёт о работе в `history/` (один файл на промпт) и запушь
   `ZeBro-pentest`.

## Чего не делать

- Не добавлять веб-версию, Docker как основной способ доставки, CI, инсталляторы.
- Не менять лицензию и `LICENSE`.
- Не переименовывать пакет `video_timer` до версии v0.3 (имя проекта `FastVT`
  выбрано 29.09.2026, пакет переименовываем отдельно).
- Не тащить новые зависимости в движок и CLI.
- Не переписывать файлы целиком ради мелкой правки.

## Готово, когда

Код есть, тест по критерию приёмки зелёный, docstring написан, спека актуальна,
коммит собран по формату выше.
